## 1. OpenXAI: Towards a Transparent Evaluation of Post hoc Model Explanations
**Agarwal, Ley, Krishna, Saxena, Pawelczyk, Johnson, Puri, Zitnik, Lakkaraju - NeurIPS 2022 Datasets & Benchmarks (arXiv:2206.11104v5)**
Read depth: **full text** (`tmp-openxai.txt`, 106 KB incl. appendices).

### What it is
Open-source benchmark framework for post hoc *feature attribution* methods on tabular
classification. Components: (i) SynthGauss synthetic data generator + 7 real tabular datasets,
16 pre-trained models (logistic regression + 2-hidden-layer ANN, 100 ReLU units/layer per
dataset); (ii) implementations of 6 explainers (LIME, SHAP, Vanilla Gradients, Gradient x Input,
SmoothGrad, Integrated Gradients) + random baseline; (iii) "twenty-two quantitative metrics"
(abstract says eleven distinct metric families) covering faithfulness, stability, fairness;
public leaderboards.

### Datasets
Synthetic (5,000 x 20, balanced); German Credit (1,000); HELOC (9,871); Adult Income (45,222);
COMPAS (6,172); Give Me Some Credit (102,209); Pima-Indians Diabetes (768); Framingham Heart
(3,658). Tabular only in first release.

### How explanation quality is evaluated (the core of the paper)
1. **Ground-truth faithfulness** (six metrics from Krishna et al. [43]): "OpenXAI leverages the
   following metrics ... to calculate the agreement between ground-truth explanations (i.e.,
   coefficients of logistic regression models) and explanations generated by state-of-the-art
   methods":
   - **Feature Agreement (FA)** - fraction of top-K features shared with GT.
   - **Rank Agreement (RA)** - shared top-K features with same rank.
   - **Sign Agreement (SA)** - shared top-K with same sign.
   - **Signed Rank Agreement (SRA)** - shared top-K with same sign AND rank.
   - **Rank Correlation (RC)** - Spearman's rho vs GT ranking.
   - **Pairwise Rank Agreement (PRA)** - fraction of feature pairs with same relative order.
   Reported as AUC over all K (FA/RA/SA/SRA) or at K = all features (RC/PRA), averaged over
   1000 test instances.
2. **Predictive faithfulness** (no ground truth needed; Petsiuk RISE-style):
   - **PGI** - "Prediction Gap on Important feature perturbation ... difference in prediction
     probability that results from perturbing the features deemed as influential"; Gaussian noise
     on top-k features, others held fixed; expectation of |y_hat − f(x')|; higher = better.
   - **PGU** - converse: perturb the *unimportant* features; lower = better. Both AUC over K.
3. **Stability**: **RIS / RRS / ROS** (Relative Input / Representation / Output Stability,
   Agarwal et al. 2022) - max ratio of percent-change in explanation to percent-change in input
   / first-layer representation / output probability over a neighborhood with unchanged
   prediction.
4. **Fairness** (Dai et al.): all above metrics averaged separately over majority vs minority
   subgroup; "If there is a huge difference in the two estimates, then we consider this to be
   evidence for unfairness."

### Ground truth used
**Architectural** (primary): GT explanations = coefficients of logistic regression models - a
transparent model whose true feature importances are known by construction. **Plus synthetic**:
SynthGauss generates K well-separated Gaussian clusters, independent features, per-cluster
Bernoulli(p=0.25) feature masks m_k and uniform weights w_k; labels from sigmoid((w_k ⊙ m_k)·x).
**Theorem 1**: "If a given dataset encapsulates the properties of feature independence,
unambiguous and well-separated local neighborhoods, and a unique ground truth explanation for
each local neighborhood, the most accurate model trained on such a dataset will adhere to the
unique ground truth explanation of each local neighborhood." This directly answers the Faber et
al. (2021) objection that data-level GT ≠ model-level GT ("When comparing to ground truth is
wrong").

### Key numbers
- With LR models, Vanilla Gradients, Integrated Gradients, and SmoothGrad score a **perfect
  1.000 on all six ground-truth faithfulness metrics on all datasets** (e.g., HELOC Table 2).
  LIME is next best (HELOC: PRA 0.923, FA 0.910, RA 0.682); SHAP and Gradient x Input are far
  behind (HELOC RA 0.029).
- Predictive faithfulness: Vanilla Grad, SmoothGrad, LIME best on PGI on average; IG on par on
  PGU.
- Stability: IG best (log-avg RIS 1.95, ROS 1.86 across datasets); Grad and Grad x Input ~3;
  LIME/SHAP/SmoothGrad/Random log RIS-ROS ≈ 10-15.
- Fairness: notable subgroup PGU disparities for **Gradient x Input and SHAP on Adult Income**.

### Stated limitations / future work (near-verbatim)
- Abstract: "While the first release of OpenXAI supports only tabular datasets, the explanation
  methods and metrics that we consider are general enough to be applicable to other data
  modalities."
- Appendix E: "we focus on these methods [LIME/SHAP/gradient-based] for the first release ...
  In the next release, we plan to evaluate and benchmark other recently proposed methods (e.g.,
  TCAV and its extensions, influence functions, etc.) as well." ... "In the next release of
  OpenXAI, we plan to include and support image and text datasets, and also add metrics and
  explanation methods that are specific to these new data modalities." Rationale for tabular
  first: high-stakes settings are predominantly tabular, and "there is no clear understanding
  as to which explanation methods perform well on what kinds of metrics even on simple,
  low-dimensional tabular datasets."

### My gap observations (not stated by authors)
- **Ground-truth circularity**: GT faithfulness is only computable against LR - a model that
  needs no post hoc explanation. Where ground truth exists, the benchmark saturates (three
  gradient methods all at 1.000), so it cannot rank methods precisely in the regime it was
  built for; for the ANN (the interesting case) only proxy PGI/PGU/stability are available.
- PGI/PGU Gaussian perturbation of tabular (incl. one-hot discrete) features produces
  off-manifold inputs; the paper does not address the OOD-evaluation critique.
- Fairness = eyeballed subgroup gap; no statistical test, no threshold for "huge difference".
- Nothing network-flavored in the 7 datasets, but tabular flow features (CICIDS-style) would
  drop into this framework unchanged - an unexploited bridge for XAI-NTC. Nobody has ported
  OpenXAI to NTC datasets.
- Theorem 1's guarantee holds for "the most accurate model"; a merely-well-trained model on
  finite data has no adherence guarantee - the gap between theorem and practice is unquantified.

## 2. Testing Intrusion Detection Systems: A Critique of the 1998 and 1999 DARPA IDS Evaluations
**John McHugh - ACM TISSEC 3(4):262-294, 2000**
Read depth: **full text** (`tmp-mchugh.txt`, via Carleton course mirror
people.scs.carleton.ca/~soma/id-2007w/readings/mchugh-darpa.pdf).

### What it is
A methodological critique (explicitly "not a direct technical contribution") of the Lincoln
Laboratory / DARPA 1998-99 IDS evaluations - the origin of the DARPA98/99 corpora from which
KDD Cup 99 and NSL-KDD descend. No ML model, no XAI content; included in corpus as the
foundational dataset-validity / evaluation-methodology reference for NTC/IDS.

### Core critiques (with quotes)
1. **Unvalidated synthetic data**: "neither analytical nor experimental validation of the
   background data's false alarm characteristics were undertaken. No detailed characterization
   of the data appears in the record and ... no rationale is given that would allow a reader to
   conclude that the systems under test should exhibit false alarm behaviors when exposed to the
   artificial background data that are similar to those that they exhibit when exposed to
   'natural' data." Internet "crud" (Bellovin, Paxson) absent from background traffic.
2. **Unrealistically low data rates**: measured training days at ~8.8-51.4 kbit/s vs 500 kbit/s
   for ~100 real workstations (PSU) - "the false alarm rates reported by Lincoln Lab may need
   to be adjusted"; "Using the evaluated systems on data streams with megabit rates might result
   in a ten- to hundred-fold increase in the false alarm rate when reported per unit time."
3. **Unrealistic attack mix**: ~300 attacks in 10 weeks; category counts 114/34/99/64
   (U2R/R2L/DoS/Probe) "surely unrealistic as current experience indicates that
   Probe/Surveillance actions are by far the most common". Attack targets heavily skewed
   (45 attacks on one host, Pascal); flat network topology precluded even running smurf.
4. **Attacker-centric taxonomy** (Weber/Kendall): "the attack manifestations have almost nothing
   in common" from the detector's viewpoint; taxonomy "offers very little support for developing
   an understanding of intrusions and their detection"; intent is not observable ("a packet that
   causes a buffer overflow is not necessarily an attack").
5. **Unit of analysis problem**: the denominator for false-alarm percentages is undefined and
   system-dependent (packet vs session vs hybrid); "These numbers are a function of the
   detection process and cannot be externally imposed."
6. **ROC misuse / pseudo-ROC**: most systems emitted 0/1 scores → single-point ROCs; the
   false-alarms-per-day x-axis is "a pragmatic, but ad hoc corruption of a basically powerful
   analytic technique," traced to 1970s Verbex wordspotting reports; "By using incomparable
   units on the two axes, the results are strongly influenced by factors, such as data rate,
   that ought to be irrelevant."
7. **Base-rate fallacy** (via Axelsson): worked example shows a 0.1% FA rate yields ~1000 false
   alarms per ~20 true intrusions; keeping operator load ≤100 events/day needs FA ≤0.0095%.
8. **No security policy** defined for the simulated base in 1998 → "the determination of
   whether a potentially hostile activity is an attack or intrusion is subjective."

### Conclusions / recommendations (near-verbatim)
"Reducing the performance of these systems to a single number ... does not appear to be
particularly useful to the investigators, since the numbers have no explanatory power." The 1999
missed-detection/false-alarm root-cause analysis "is probably much more useful in improving IDS
systems." Recommendations: solve the unit-of-analysis problem ("Requiring each system to report
both detections and nondetections might be a fruitful approach"); "There is a need for
calibrated and validated artificial test data sets or test data generators"; evaluate commercial
baselines independently; build an ongoing "attack on demand" repository; fund data validation
and pilot studies.

### Stated limitations of the critique itself
Scope "limited ... primarily ... the network data recorded at the boundary"; BSM audit and file
system dump data not examined in detail; AFRL real-time evaluation not considered; relies only
on the public record ("relying on such [restricted] sources would be bad scholarship"); 1999
evaluation discussed only from slide decks, "no publications as yet."

### My gap observations
- Every XAI-NTC paper that trains on KDD99/NSL-KDD inherits these defects: **explanations
  faithfully describing a model trained on unvalidated, unrealistically mixed synthetic data
  are explanations of a simulation artifact.** Explanation-vs-ground-truth agreement on
  DARPA-lineage labels is bounded by label quality that was never established.
- McHugh's complaint that scores "have no explanatory power" and his praise of the 1999
  error-analysis exercise is effectively a 2000-era demand for explainability of evaluation
  results - a useful framing citation for the journal paper's motivation.
- The unit-of-analysis problem recurs unresolved in XAI-NTC: per-packet vs per-flow vs
  per-session attribution granularity is today's version of the same undefined denominator.
- Ironic and instructive: the *synthetic-data-with-known-ground-truth* strategy that modern XAI
  benchmarks (OpenXAI in this batch) adopt for rigor is exactly what McHugh criticizes when the
  synthesis itself is unvalidated - construction validity precedes ground-truth validity.

## 3. A Diagnostic Study of Explainability Techniques for Text Classification
**Atanasova, Simonsen, Lioma, Augenstein - EMNLP 2020 (arXiv:2009.13295)**
Read depth: **full text** (`tmp-diagnostic-study.txt`).

### What it is
Unified comparison of 9 saliency-technique variants x 3 model architectures (CNN, LSTM,
Transformer/BERT; plus randomly-initialized twins) x 3 text classification tasks with
human-annotated rationales, via a "comprehensive list of diagnostic properties." Code:
github.com/copenlu/xai-benchmark.

### Datasets (all with human token-level rationale annotations)
e-SNLI (549,367 train; avg 27.4 tokens/instance, 5.3 annotated); Movie Reviews (Zaidan; 1,399
train; 834.9 tokens, 56.18 annotated - labeled "IMDB" in results tables); Tweet Sentiment
Extraction (21,983 train; 20.5 tokens, 9.99 annotated).

### Explainers
Gradient-based: Saliency, InputXGradient, Guided Backpropagation - each with mean (mu) and L2
aggregation over embedding dims. Perturbation: Occlusion (zero baseline), Shapley Value
Sampling. Simplification: LIME. Plus random baseline.

### How explanation quality is evaluated - the 5 diagnostic properties (+ FLOPs)
1. **Agreement with human rationales (HA)**: "Average Precision (AP) of produced saliency
   scores ... comparing them to the gold saliency annotations", averaged = **MAP**. Explicit
   caveat: "While it does not necessarily mean that the saliency scores explain the predictions
   of a model, we assume that explanations with high agreement scores would be more
   comprehensible for the end-user as they would adhere more to human reasoning."
2. **Confidence Indication (CI)**: Saliency Distance between predicted-class and other-class
   scores; a logistic regression predicts model confidence from SD; report **MAE** of predicted
   vs actual confidence.
3. **Faithfulness (F)**: mask 0,10,...,100% of tokens in decreasing saliency order; **AUC-TP**
   "area under the threshold-performance curve" of performance drop (avoids fixing an arbitrary
   deletion threshold); compared against a random saliency map.
4. **Rationale Consistency (RC)**: Spearman rho between (a) distance of activation maps
   (averaged across layers/nodes) of two models - same architecture, different seeds, or
   randomly initialized - and (b) distance of their explanations, on the same instance.
5. **Dataset Consistency (DC)**: Spearman rho between activation-map distance and explanation
   distance for *pairs of instances* on the same model.

### Ground truth used
**human_expert** - gold token-level saliency annotations by humans for all three datasets
(the HA property). The other four properties are model-internal proxies, no ground truth.

### Key numbers / findings
- Table 3 (mean of all normalized property measures): "gradient-based explainability techniques
  always have the best or the second-best performance ... across all three model architectures
  and all three downstream tasks." E.g., CNN/e-SNLI InputXGrad-L2 0.881, Saliency-L2 0.875;
  Transformer/e-SNLI LIME 0.809, InputXGrad-L2 0.796.
- Mean-aggregation variants (InputXGrad-mu, GuidedBP-mu) among the worst - "the mean smooths
  out any differences"; L2 amplifies; mu-variants' MAP "close to or even worse than those from
  the randomly initialized models."
- ShapSampl/LIME/Occlusion win only Confidence Indication ("expected, as they compute the
  saliency of words based on differences in the model's confidence"), but "take considerably
  more time to compute and have worse performance for all other diagnostic properties."
- Higher-performing models agree more with human rationales (Transformer MAP > CNN/LSTM), but
  "models with high Faithfulness scores do not necessarily have high Human agreement scores and
  vice versa. This suggests that these two are indeed separate diagnostic properties."
- Explainability works better on small/linear architectures: "performance of the explainability
  tools can be worse for large complex architectures with a huge number of neural nodes, like
  the Transformer one, and perform better for small, linear architectures like the CNN."

### Stated limitations / future work (near-verbatim)
- "there are also datasets (Clark et al., 2019; Khashabi et al., 2018) with annotations at the
  sentence-level, which would require other model architectures, so we leave this for future
  work."
- HA caveat quoted above (plausibility, not model-faithfulness).
- On deletion curves: cites Feng et al. 2018 - "models remain confident about their prediction
  even after stripping most input tokens" - motivating the additional properties.
- For images "we only found one relevant dataset - 536 manually annotated object bounding boxes
  for VQA" (scarcity of human rationale data outside NLP).
- No dedicated limitations section (pre-mandate EMNLP); several result explanations flagged as
  hypotheses/conjecture.

### My gap observations
- RC/DC rest on an unvalidated assumption that **activation-map distance = reasoning-path
  similarity**; distance averaged "across layers and neural nodes" mixes incomparable scales
  across architectures.
- The final ranking averages normalized property scores into one number per method - the exact
  single-number reduction McHugh warns has "no explanatory power"; trade-offs are hidden.
- Human rationale ground truth exists because NLP tokens are human-legible. The paper's own
  observation about image-data scarcity is far worse for traffic: **no human-annotated salient
  bytes/packets/flows dataset exists at all for NTC** - the HA property is untransferable
  as-is; this is a concrete gap our paper can name.
- Masking with a [MASK]/zero token is an OOD intervention; the paper acknowledges via Feng et
  al. but still uses AUC-TP as its faithfulness measure.

## 4. Accurate Decentralized Application Identification via Encrypted Traffic Analysis Using GNNs (GraphDApp)
**Shen, Zhang, Zhu, Xu, Du - IEEE TIFS vol. 16, 2021, pp. 2367-2380**
Read depth: **full text** (`tmp-graphdapp.txt`, via thucsnet.com author mirror).

### What it is
DApp fingerprinting (identifying which Ethereum DApp a user visits from encrypted traffic).
Proposes **Traffic Interaction Graph (TIG)**: per-flow graph where vertices = packets (attribute
= signed packet length; + downstream / − upstream), intra-burst edges chain consecutive
same-direction packets, inter-burst edges connect first/last vertices of consecutive bursts.
Classifier: GIN-style GNN - MLP layers with injective sum aggregation ((1+eps)·h_v + sum of
neighbors, Xu et al. "How powerful are GNNs"), Jumping-Knowledge-style concatenated readout
across layers, FC + softmax, cross-entropy, Adam. Timestamps deliberately excluded. First 25
packets per flow used.

### Datasets (self-collected, real-world)
Closed world: top-40 Ethereum DApps, 155,500 flows, captured by Wireshark on lab routers at
Chinese university campuses, Chrome only. Open world: 1,260 unmonitored DApps, 14,000 flows
(each visited once). Also 15 mobile apps, 54,000+ flows (downstream only) from their earlier
work. 10-fold CV; CPU-only server.

### Key numbers
- Representation analysis (Fig. 4): with packet-length sequences only 4/40 DApps have
  intra-class distance below the minimum inter-class distance; with TIG + graph edit distance,
  21/40. 15 DApps vs 1 DApp have intra-class distance above the median inter-class distance.
- Closed world: accuracy **0.8922 ± 0.0011**, best of 7 methods (Markov SSL/TLS, AppScanner,
  Feature Fusion RF, DeepFingerprinting CNN+direction, CNN+length, LSTM+length); 5 DApps at
  1.0; 67.5% of DApps above 0.9; shortest total training time among all methods.
- Open world: TPR 0.99 / FPR 0.05 (stable from 720 unmonitored DApps); **AUC 0.9973**;
  precision 0.96 at recall 1.0.
- Mobile apps: accuracy ~1.0 (CNN+D collapses to 0.627 on downstream-only flows).

### How explanation quality is evaluated
**None.** There are no explanations. No attribution, no saliency, no post hoc method, no
interpretability claim beyond: (a) Fig. 3 qualitative eyeballing of TIG shapes ("Aigang owns
spindle-shaped TIGs ... Aragon has simple and compact TIGs, while AaveProtocol exhibits complex
and fish-shaped TIGs"); (b) Fig. 4 quantitative intra-/inter-class distance separability of the
*input representation* (graph edit distance with node-substitution cost = Euclidean, node
ins/del 90, edge ins/del 15) - a representation-informativeness argument, not an explanation
evaluation. Confusion matrix and ROC/PR curves are classification metrics only.

### Ground truth used (for explanations)
**none** (no explanations exist; class labels come from controlled visits during collection).

### Stated limitations / future work (verbatim, Section VI)
"There are mainly two limitations with our method. The first limitation is that GraphDApp needs
a relatively long time to label an unknown flow. This can be solved by appropriately reducing
the number of packets in TIGs to shorten feature extraction time, and employing less MLP layers
and hidden units to accelerate the prediction speed. The second limitation is that, as a
fingerprinting solution, when the fingerprints of an application changes, the accuracy will
decrease accordingly. To address this problem, we can regularly update the TIGs of the
application and fine-tune the parameters in the classifier. In the future work, we will further
investigate techniques to make GraphDApp more adaptable to traffic changes."

### My gap observations
- A top-venue (TIFS) encrypted-traffic GNN with **zero explainability**: the model is exactly
  the class GNNExplainer / PGExplainer / subgraph-attribution methods target, and TIG subgraphs
  (bursts, handshake vs record phases) have natural domain semantics - an ideal, untouched
  XAI-NTC testbed. GraphDApp is a concrete exhibit for "NTC SOTA ships uninterpreted."
- The Fig. 3 "shape" narrative is precisely the informal plot-only interpretability our survey
  criticizes: n=1 randomly chosen flow per DApp, no quantification of which structural motifs
  drive decisions.
- Dataset validity echoes McHugh: single browser, lab campuses, controlled visits; no drift or
  cross-network generalization test (their own limitation 2 concedes fingerprint drift);
  open-world unmonitored DApps visited once each following website-fingerprinting convention.
- Authors' interpretability-adjacent claim - GNN expressiveness bounded by the WL test - is a
  statement about the *classifier's* discriminative power, never connected to explaining
  individual decisions.

## 5. Malware traffic classification using convolutional neural network for representation learning
**Wang, Zhu, Zeng, Ye, Sheng - ICOIN 2017, pp. 712-717, DOI 10.1109/ICOIN.2017.7899588**
Read depth: **abstract_only** (no OA copy: IEEE paywalled; Unpaywall/S2/fatcat empty;
ResearchGate direct PDF behind JS challenge; Internet Archive offline during retrieval;
author's DeepTraffic GitHub repo contains code/dataset but not the PDF). Abstract recovered in
full via OpenAlex; secondary details cross-checked against multiple citing surveys.

### Abstract (full, via OpenAlex)
"Traffic classification is the first step for network anomaly detection or network based
intrusion detection system... we first presented a new taxonomy of traffic classification from
an artificial intelligence perspective, and then proposed a malware traffic classification
method using convolutional neural network by taking traffic data as images. This method needed
no hand-designed features but directly took raw traffic as input data of classifier. To the
best of our knowledge this interesting attempt is the first time of applying representation
learning approach to malware traffic classification using raw traffic data. We determined that
the best type of traffic representation is session with all layers through eight experiments.
The method is validated in two scenarios including three types of classifiers and the
experiment results show that our proposed method can satisfy the accuracy requirement of
practical application."

### What is reliably known (secondary sources; treat cautiously)
Introduced the **USTC-TFC2016** dataset (10 malware families + 10 benign applications; pcaps;
preprocessing toolkit USTC-TK2016 in github.com/echowei/DeepTraffic). Pipeline: split raw pcap
by flow/session; take first 784 bytes; render as 28x28 grayscale image; LeNet-5-style 2D CNN.
Eight experiments compare {flow, session} x {all layers, L7}; session+all-layers best. Three
classifiers: binary (malware vs benign), 10-class malware, 20-class mixed. Widely quoted
average accuracy ~**99.41%** (from citing literature, not verified against the paper itself).

### How explanation quality is evaluated
**None** (per abstract and all secondary descriptions: accuracy-driven; no attribution or
explanation content; "representation learning" refers to feature learning, not
interpretability).

### Ground truth used (for explanations)
**none**.

### Stated limitations / future work
**Not retrievable** - the abstract states none, and the full text could not be legally
obtained. Do not cite limitations for this paper without obtaining the PDF (try institutional
IEEE Xplore access: document 7899588).

### My gap observations
- This is the canonical origin of the **raw-bytes-as-grayscale-image** pipeline that a large
  share of later XAI-NTC papers apply saliency methods to. Whatever the pixels/saliency
  highlight is downstream of this representation choice, made here on accuracy grounds alone.
- "Session with all layers" retains headers - IP addresses, ports - creating a known
  **shortcut/label-leakage risk** in USTC-TFC2016 (later work masks or randomizes headers).
  A saliency map on such inputs that highlights header bytes may be evidence of dataset
  artifact rather than malware semantics. This makes the paper's pipeline both the most common
  XAI-NTC substrate and a cautionary example of why explanation ground truth is needed.
- The 28x28 truncation (784 bytes) and image metaphor impose CNN-friendly but semantically
  arbitrary structure (byte 29 is "below" byte 1); XAI methods borrowed from vision inherit
  assumptions (spatial locality) that traffic bytes do not satisfy - rarely acknowledged in
  follow-ups.

## 6. On the (In)fidelity and Sensitivity of Explanations
**Yeh, Hsieh, Suggala, Inouye, Ravikumar - NeurIPS 2019 (arXiv:1901.09392v4)**
Read depth: **full text** (`tmp-infidelity.txt`).

### What it is
Proposes two *objective* evaluation measures for saliency explanations of black-box predictors
and analyzes their optima.
- **Infidelity** (Def 2.1): INFD(Phi,f,x) = E_{I~mu_I} [ (I^T Phi(f,x) − (f(x) − f(x−I)))^2 ]
  - expected squared gap between the explanation's predicted effect of a *significant*
  perturbation I and the function's actual change. Generalizes Ancona et al.'s subset
  correlation; perturbation families: difference to baseline, subsets to baseline, noisy
  baseline, multiple baselines.
- **Max-sensitivity** (Def 3.1): SENS_MAX = max_{||y−x||<=r} ||Phi(f,y) − Phi(f,x)|| - maximum
  explanation change under insignificant input perturbation; "can be robustly estimated via
  Monte-Carlo sampling" (unlike local-Lipschitz variants which can be unbounded for ReLU nets).

### Theory
- Prop 2.1: the infidelity-optimal explanation = smoothing (SmoothGrad-like, kernel I·I^T) of
  Integrated Gradients - "a novel combination of two popular explanation methods."
- Props 2.2-2.5: completeness-axiom methods (IG, DeepLift, LRP), vanilla gradient, occlusion-1,
  and Shapley value are each infidelity-optimal under specific perturbation distributions -
  infidelity is a unifying framework.
- Two new explanations by optimizing infidelity under new perturbations: **NB** (noisy
  baseline; robust completeness) and **Square** (uniform random square patches - image-specific;
  random pixel subsets deemed "somewhat meaningless" and full SHAP subsets infeasible).
- Thm 4.1/4.2: kernel smoothing provably lowers sensitivity, and (under C1 <= 1/sqrt(2)
  conditions) lowers infidelity too - "there need not exist a trade-off between sensitivity and
  infidelity"; "modest smoothing actually improves infidelity."

### Experiments / how the *metric itself* is validated
- MNIST, CIFAR-10, ImageNet (Grad, IG, GBP, KernelSHAP; +SG variants; NB; Square). Local
  variants restricted to MNIST. Table 1: SmoothGrad improves both SENS_MAX and INFD for every
  base method on every dataset (e.g., MNIST local: Grad 0.86/4.12 → Grad-SG 0.23/1.84; NB
  0.35/0.51). NB and Square get the lowest infidelity - "as expected, since they explicitly
  optimize the corresponding infidelity." Sanity-check experiment: under SHAP's perturbation,
  SHAP has the lowest infidelity.
- **Human evaluation with approximated ground truth** (follows TCAV's setup [18]): constructed
  2-class dataset (bird/frog); image in one half of the canvas, text caption in the other; with
  noise p=0 the trained model "solely relies on the image (accuracy for image only input is
  0.9, but accuracy for caption only input is 0.5)"; with p=0.6 it "only relies on the caption
  (0.98 vs 0.5)" - i.e., which half the model uses is established **interventionally by
  half-input ablation**. 16 test users x 8 tasks (2 models x 4 explanations) judge which half
  the model relies on from the explanation. Results (Table 3): human accuracy Grad 0.47,
  Grad-SG 0.50, IG 0.53, **OPT 0.88**; infidelity 0.55 / 0.38 / 0.35 / 0.00 - "the infidelity
  aligns with human evaluation result in general."
- **Sanity check** (Adebayo et al.): rank correlation of explanations between pretrained and
  last-layer-randomized ResNet-50 (Table 2): without abs, all pass (0.10-0.18); with absolute
  values correlations are high (~0.57-0.62) except **Square 0.28** - "supports the hypothesis
  that an explanation with low infidelity is also faithful to the model."

### Ground truth used
**synthetic** - a constructed two-block (image half / caption half) dataset where the feature
block the model relies on is known ("approximated ground truth"), with the reliance verified
interventionally via half-input ablation accuracies. (Also human subjects, but humans serve as
explanation *consumers* being scored against this constructed ground truth, not as the ground
truth source.)

### Stated limitations (scattered; no dedicated section)
- "the infidelity measure, while objective, may not capture all the desiderata of a successful
  explanation."
- "sensitivity provides only a partial measure of what is desired from an explanation ... the
  optimal explanation that minimizes the above max-sensitivity measure is simply a constant
  explanation that just outputs a (potentially nonsensical) constant value."
- Adversarial-training alternative "requires that we be able to modify the given predictor
  function itself, which might not always be feasible."
- "we restrict local variants of the explanations to MNIST, since sensitivity of function
  values given pixel perturbations make more sense for grayscale rather than color images."

### My gap observations
- **Self-referential headline result**: NB/Square achieve the lowest infidelity *by
  construction* (they optimize it), and the SHAP sanity check shows the winner flips with the
  perturbation distribution - infidelity rankings are relative to a designer-chosen mu_I. A
  method author can "metric-shop" the perturbation. The paper is candid about this but the
  implication for cross-paper comparability is large.
- Human study is small (16 users, 8 tasks each) and the ground truth is block-granular
  (half-image), far coarser than pixel attributions being judged.
- For NTC transfer: infidelity requires *meaningful significant perturbations* I of the input.
  Perturbing packet bytes/flow features toward a "baseline" violates protocol syntax and flow
  semantics (there is no natural zero-baseline packet); Square's spatial-patch logic has no
  analog in byte sequences. Defining a valid mu_I for traffic is an open problem nobody in the
  NTC literature has addressed - a precise, citable gap.
- Sensitivity-infidelity smoothing results assume continuous input neighborhoods; traffic
  features are largely discrete/categorical, where "small r-ball perturbations" are undefined.

## Batch-level synthesis for the journal paper

1. **Where explanation ground truth exists, it is manufactured** - LR coefficients and provably
   aligned synthetic clusters (OpenXAI), human token rationales (Diagnostic Study), constructed
   two-block inputs with interventionally verified reliance (Yeh). Each construction exploits a
   property (transparent model, human-legible tokens, separable input blocks) that **network
   traffic lacks**: no transparent SOTA traffic model, no human-annotated salient bytes corpus,
   no semantically valid input-block ablations for encrypted flows.
2. **Proxy metrics are perturbation-relative and partly circular**: infidelity crowns whatever
   optimizes it; OpenXAI's GT metrics saturate exactly where GT is available; deletion/masking
   curves (AUC-TP, PGI/PGU) are all OOD interventions, acknowledged (Feng et al. citation;
   Yeh's caveats) but still standard.
3. **The NTC papers in the batch confirm the explainability vacuum**: GraphDApp (TIFS 2021,
   GNN) and Wang 2017 (the field's canonical CNN pipeline) contain zero explanation evaluation;
   interpretability appears only as eyeballed figure narration. Their stated limitations are
   about speed and drift, never opacity.
4. **McHugh closes the loop underneath everything**: the dominant NTC benchmarks descend from
   an evaluation whose data generation was never validated. Explanation-quality claims measured
   against labels of DARPA lineage compound two unvalidated layers (data ground truth and
   explanation ground truth). His 2000 recommendations - validated/calibrated data generators,
   measures with explanatory power, resolved units of analysis - read as a to-do list that
   XAI-NTC evaluation still has not completed.
